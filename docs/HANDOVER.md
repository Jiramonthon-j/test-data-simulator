# เอกสารส่งมอบระบบ — Intelligent Test Data Simulator (ITDS)

เอกสารนี้อธิบายสถานะของระบบที่ส่งมอบ วิธีดูแลระบบ และวิธีย้ายระบบไปอยู่ภายใต้บัญชีของบริษัทในภายหลัง วิธีใช้งานหน้าเว็บอยู่ใน [`USER_GUIDE.md`](USER_GUIDE.md)

## อัปเดตโค้ด

- **แก้ Backend (`apps-script/*.gs`):** วางโค้ดใหม่ใน Apps Script → **Deploy › Manage deployments** → เลือก deployment ที่ใช้อยู่ → ไอคอนดินสอ → **Version: New version** → **Deploy** (URL เดิมไม่เปลี่ยน)
- **แก้หน้าเว็บ (`index.html`):** แก้ใน repo `test-data-simulator` แล้วคัดลอกไฟล์ไปที่ repo `itds-qa/itds-qa.github.io` push ทั้งสอง GitHub Pages อัปเดตเองภายใน 1–2 นาที เปิดเว็บด้วย Ctrl+F5
- **ตรวจว่าใช้ Backend ตัวล่าสุด:** ใต้กล่องล็อกอินแสดง `Backend version` ต้องตรงกับค่า `BACKEND_VERSION` ใน `apps-script/Code.gs`
- **เปลี่ยน Gemini API Key:** Apps Script → **Project Settings › Script Properties** → แก้ค่า `GEMINI_API_KEY` → Save (มีผลทันที ไม่ต้อง Deploy ใหม่)

## ถ้า Web App ถูก Google ระงับ

**อาการ:** หน้าเว็บแจ้ง "เชื่อมต่อ Backend ไม่ได้" และเมื่อเปิด Web App URL ตรง ๆ ขึ้นว่า "คุณไม่สามารถเข้าถึงเอกสารนี้ เนื่องจากมีการละเมิดข้อกำหนดในการให้บริการ"

เกิดจากระบบตรวจจับอัตโนมัติของ Google (มักเกิดกับบัญชีใหม่ที่เปิด Web App ซึ่งมีหน้าล็อกอินให้ทุกคนเข้าได้) ข้อมูลในชีตไม่หาย Google บล็อกเฉพาะ URL ของ deployment นั้น

**วิธีแก้ (ประมาณ 5 นาที):**
1. Apps Script → **Deploy › New deployment** → Web app → Execute as: **Me** / Who has access: **Anyone** → Deploy
2. ทดสอบ URL ใหม่ในหน้าต่าง Incognito โดยต่อท้าย `?action=ping` ต้องได้ข้อความที่มี `"pong"`
3. แก้ `BACKEND_URL` ใน `index.html` เป็น URL ใหม่ ทั้งใน `test-data-simulator` และ `itds-qa.github.io` แล้ว push ทั้งสอง
4. **Deploy › Manage deployments** → เก็บถาวร (Archive) deployment ตัวเก่า

**ป้องกัน:** ให้บัญชีระบบมีเบอร์โทรยืนยันตัวตนเสมอ อย่าแจกลิงก์หน้าเว็บในที่สาธารณะ และถ้าโดนซ้ำ ควรย้ายไปติดตั้งด้วยบัญชี Google Workspace ของบริษัท เพราะการโดนหลายครั้งอาจทำให้ทั้งบัญชีถูกระงับ

## การย้ายระบบไปบัญชีบริษัท

ทำเมื่อบริษัทพร้อมรับระบบไปดูแลเอง ระบบใหม่จะเป็นอีกชุดหนึ่ง (ชีตใหม่ ผู้ใช้ใหม่) ข้อมูลเดิมในชีตของผู้พัฒนาไม่ได้ย้ายตามไปอัตโนมัติ

ในโค้ดไม่มีอีเมลหรือรหัสลับฝังอยู่ ค่าเหล่านี้ทั้งหมดถูกกำหนดตอนติดตั้งตามขั้นตอนด้านล่าง ทำทุกขั้นตอนโดย**ล็อกอินด้วยบัญชี Google ของบริษัทบัญชีเดียวตลอด**

### สิ่งที่ผูกกับบัญชีและวิธีกำหนด

| สิ่งที่ใช้ | ผูกอยู่กับ | กำหนดในขั้นตอน |
| :--- | :--- | :--- |
| อีเมลผู้ส่ง (OTP, แจ้งเตือนความปลอดภัย, ผลคำขอต่าง ๆ) | บัญชี Google ที่ Deploy Apps Script | ขั้นตอนที่ 5 |
| อีเมลผู้รับคำขอของ Super Admin หลัก | คอลัมน์ `email` ของบัญชี `Admin123` ในชีต `Users` | ขั้นตอนที่ 6 |
| Gemini API Key | Script Properties ชื่อ `GEMINI_API_KEY` | ขั้นตอนที่ 3 |
| Google Sheet ฐานข้อมูล, โฟลเดอร์สำรองข้อมูลและรายงานใน Drive | บัญชีที่สร้างชีต (โฟลเดอร์สร้างให้อัตโนมัติ) | ขั้นตอนที่ 1–2 |
| หน้าเว็บเชื่อมไปที่ backend ไหน | ตัวแปร `BACKEND_URL` ใน `index.html` | ขั้นตอนที่ 7 |

> ทำทุกขั้นตอนโดย **ล็อกอินด้วยบัญชี Google ของบริษัทบัญชีเดียวตลอด** ถ้าสลับบัญชีกลางคัน ไฟล์และสิทธิ์จะกระจายไปอยู่คนละบัญชี

### ขั้นตอนที่ 0 — เตรียมก่อนเริ่ม

- บัญชี Google ของบริษัท 1 บัญชีสำหรับระบบนี้ (แนะนำบัญชีกลาง เช่น `qa-tools@<บริษัท>.com` ไม่ใช่บัญชีของพนักงานคนใดคนหนึ่ง)
- อีเมลของผู้ที่จะเป็น Super Admin หลัก (ใช้รับคำขอสมัคร Super Admin และคำขอลบบัญชี)
- ไฟล์ทั้งหมดใน repo นี้

**ข้อจำกัดที่ควรรู้:**

| | บัญชี Gmail ทั่วไป | บัญชี Google Workspace |
| :--- | :--- | :--- |
| ส่งอีเมลจาก Apps Script | ประมาณ 100 ฉบับ/วัน | ประมาณ 1,500 ฉบับ/วัน |
| Gemini API แบบฟรี | จำกัดจำนวนคำขอต่อนาที/ต่อวัน | เหมือนกัน (ถ้าใช้หนักควรเปิดแบบเสียเงิน) |

Rule-Based Mode ไม่เรียก Gemini จึงไม่กินโควตา AI

### ขั้นตอนที่ 1 — สร้าง Google Sheet และวางโค้ด

1. ไปที่ [sheets.google.com](https://sheets.google.com) สร้างสเปรดชีตเปล่า ตั้งชื่อ เช่น `ITDS Database`
2. เมนู **Extensions › Apps Script**
3. วางโค้ดจากโฟลเดอร์ `apps-script/` ให้ครบ 4 ไฟล์ (กด **+ › Script** เพื่อเพิ่มไฟล์ และตั้งชื่อให้ตรง):
   - `Code.gs` (วางทับโค้ดเริ่มต้น)
   - `RuleDispatcher.gs`
   - `RuleCompilerPrompt.gs`
   - `InsuranceReferenceData.gs`
4. กดบันทึก (Ctrl+S)

### ขั้นตอนที่ 2 — รัน `setupSheet` ครั้งแรก

1. ในแถบด้านบนของ editor เลือกฟังก์ชัน `setupSheet` แล้วกด **Run**
2. หน้าต่างขอสิทธิ์จะขึ้น ให้เลือกบัญชีบริษัท → **Advanced › Go to (ชื่อโปรเจกต์)** → **Allow**
3. เมื่อสำเร็จจะมี popup แจ้ง และในสเปรดชีตจะมีแท็บต่าง ๆ เพิ่มขึ้น เช่น `Users`, `ActivityLogs`, `RuleTemplates`
4. ระบบสร้างบัญชีเริ่มต้นให้ 1 บัญชี: `Admin123` (Super Admin หลัก) รหัสผ่านเริ่มต้นดูได้ในคอมเมนต์บรรทัดแรก ๆ ของ `Code.gs` — **ต้องเปลี่ยนรหัสผ่านในขั้นตอนที่ 6**

### ขั้นตอนที่ 3 — ตั้งค่า Gemini API Key

1. ไปที่ [aistudio.google.com/apikey](https://aistudio.google.com/apikey) ด้วยบัญชีบริษัท → **Create API key**
2. กลับไปที่ Apps Script → ไอคอนเฟือง **Project Settings** → **Script Properties** → **Add script property**
3. Property: `GEMINI_API_KEY` / Value: คีย์ที่ได้ → **Save**

คีย์นี้อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ปรากฏในหน้าเว็บ

### ขั้นตอนที่ 4 — นำเข้ากฎของ Rule-Based Mode (ถ้าต้องการใช้กฎตัวอย่าง)

1. เปิดไฟล์ `templates/RuleTemplates_Insurance.xlsx` (มีกฎตัวอย่างด้านประกันราว 96 แถว)
2. คัดลอกข้อมูลทุกแถว (ไม่รวมหัวตาราง) ไปวางต่อท้ายในแท็บ `RuleTemplates` ของสเปรดชีต โดยคอลัมน์ต้องเรียงเหมือนกัน: `table_name`, `column_name`, `generator`, `param_json`, `notes`

ถ้าไม่นำเข้า Rule-Based Mode จะแจ้งว่าไม่พบกฎ และให้ผู้ใช้ส่งคำขอถึง Super Admin ได้ตามปกติ

### ขั้นตอนที่ 5 — Deploy เป็น Web App

1. มุมขวาบน **Deploy › New deployment** → ไอคอนเฟือง → **Web app**
2. ตั้งค่า:
   - **Execute as:** Me — บัญชีนี้จะเป็น **ผู้ส่งอีเมลทุกฉบับ** ของระบบ
   - **Who has access:** Anyone (ถ้าเลือกแบบอื่น หน้าเว็บจะเรียก backend ไม่ได้)
3. กด **Deploy** แล้วคัดลอก **Web app URL** (`https://script.google.com/macros/s/.../exec`)

> ทุกครั้งที่แก้โค้ด `.gs` ต้องกด **Deploy › Manage deployments › ไอคอนดินสอ › Version: New version › Deploy** ใช้ deployment เดิมแบบนี้ URL จะไม่เปลี่ยน ถ้ากด New deployment จะได้ URL ใหม่และต้องแก้ `index.html` ตามทุกครั้ง

### ขั้นตอนที่ 6 — ตั้งค่าบัญชี Super Admin หลัก

1. ทำขั้นตอนที่ 7 ก่อนเพื่อให้เปิดหน้าเว็บได้ แล้วล็อกอินด้วย `Admin123`
2. กด **เปลี่ยนรหัสผ่าน** ที่หัว Dashboard แล้วตั้งรหัสใหม่ที่ไม่เปิดเผย
3. ไปที่ **จัดการผู้ใช้งาน** → หาบัญชี `Admin123` → **ตั้ง/แก้ไขอีเมล** → ใส่อีเมลของผู้ดูแลระบบ
   - อีเมลนี้ใช้รับคำขอสมัคร Super Admin และคำขอลบบัญชี
   - ใช้รับ OTP ตอนลืมรหัสผ่าน ถ้าไม่ตั้งไว้ บัญชีนี้จะกู้รหัสผ่านเองไม่ได้

### ขั้นตอนที่ 7 — เชื่อมหน้าเว็บกับ backend

1. เปิด `index.html` ค้นหาบรรทัด
   ```js
   const BACKEND_URL = "PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
2. แทนค่าในเครื่องหมายคำพูดด้วย Web app URL จากขั้นตอนที่ 5 แล้วบันทึก
3. ทดสอบด้วยการเปิดไฟล์ `index.html` ในเบราว์เซอร์ได้ทันที

**การนำหน้าเว็บขึ้นให้ทีมใช้** (`index.html` เป็นไฟล์ static ไฟล์เดียว เลือกวิธีใดวิธีหนึ่ง):

| วิธี | เหมาะกับ |
| :--- | :--- |
| เว็บเซิร์ฟเวอร์ภายในบริษัท | ใช้ภายในองค์กร ควบคุมการเข้าถึงได้ |
| GitHub Pages | repo แบบ Private ต้องใช้ GitHub แผน Team/Enterprise |
| แชร์ไฟล์ `index.html` ให้เปิดในเครื่อง | ทดลองใช้ในทีมเล็ก |

### ขั้นตอนที่ 8 — ตรวจความพร้อมและปิดสิทธิ์แชร์

1. ในสเปรดชีต เมนู **เครื่องมือแอดมิน › ตรวจสอบความพร้อมก่อน Deploy** ต้องผ่านครบทุกข้อ
2. ตั้งสิทธิ์แชร์สเปรดชีตเป็น **Restricted** (เฉพาะผู้ที่ได้รับเชิญ) เพราะชีตเก็บข้อมูลผู้ใช้
3. (แนะนำ) เปิด **เครื่องมือแอดมิน › เปิดระบบสำรองข้อมูลอัตโนมัติ** และ **เปิดระบบย้ายข้อมูลเก่าไปแท็บสำรองอัตโนมัติ**
