## 1. ภาพรวมและบทบาทผู้ใช้

### ขั้นตอนการทำงานหลัก

```
กรอกโครงสร้างตาราง + เงื่อนไข  →  สร้างข้อมูล  →  จุดพักตรวจคุณภาพ  →  ตรวจ/แก้ในตาราง  →  Commit ลงฐานข้อมูล  →  ดาวน์โหลด SQL / CSV / JSON
```

ระบบออกแบบเป็น **Human-in-the-Loop**: AI หรือโค้ดเป็นผู้สร้างข้อมูล แต่คนต้องตรวจและยืนยันก่อนบันทึกจริงทุกครั้ง

### โหมดการสร้างข้อมูล

| | Rule-Based Mode | Legacy Mode (AI) |
| :--- | :--- | :--- |
| ใครสร้างข้อมูล | โค้ด ตามกฎในชีต `RuleTemplates` | Gemini AI ตามเงื่อนไขที่พิมพ์ |
| ใช้โควตา AI | ไม่ใช้ | ใช้ 2 ครั้งต่อการกดสร้าง 1 ครั้ง |
| ผลลัพธ์ | สม่ำเสมอ คาดเดาได้ | ยืดหยุ่น เข้าใจเงื่อนไขภาษาคน |
| ต้องมี DDL Script | ต้องมี | ไม่บังคับ |
| ต้องมีกฎล่วงหน้า | ต้องมีครบทุกคอลัมน์ | ไม่ต้อง |

### บทบาทผู้ใช้

| บทบาท | สิทธิ์ |
| :--- | :--- |
| QA Tester, Developer, Business Analyst, System Analyst | ใช้งานทุกเมนูหลัก สร้างข้อมูล Commit ดูประวัติ และส่งคำขอถึงผู้ดูแลระบบ |
| Super Admin | ทุกอย่างข้างบน รวมถึงจัดการผู้ใช้งาน เปิดชีตกฎ ตอบคำขอของผู้ใช้ทุกคน |
| Super Admin หลัก (`Admin123`) | เหมือน Super Admin และเป็นผู้อนุมัติการสมัคร Super Admin ใหม่ บัญชีนี้ลบไม่ได้ |

### บัญชีผู้ดูแลระบบ (Super Admin หลัก)

| | |
| :--- | :--- |
| Username | `Admin123` |
| Email | อีเมลผู้ดูแลระบบที่ตั้งไว้ในหน้าจัดการผู้ใช้งาน (แจ้งตอนส่งมอบ) |
| Password | ส่งมอบแยกจากเอกสารนี้ (ไม่เก็บไว้ใน repo) |

- บัญชีนี้อนุมัติการสมัคร Super Admin ใหม่ และลบออกจากระบบไม่ได้

- ผู้รับมอบควรเปลี่ยนรหัสผ่านทันทีหลังรับมอบ (ปุ่ม **เปลี่ยนรหัสผ่าน** ที่หัว Dashboard)

## 2. สมัครสมาชิก เข้าสู่ระบบ และลืมรหัสผ่าน

### สมัครสมาชิก

กด **"ยังไม่มีบัญชีผู้ใช้งาน? ลงทะเบียนที่นี่"** ที่หน้าเข้าสู่ระบบ การสมัครมี 2 ขั้นตอน

**ขั้นตอนที่ 1/2 — ชื่อผู้ใช้ อีเมล รหัสผ่าน**

| ช่อง | เงื่อนไข |
| :--- | :--- |
| ชื่อผู้ใช้งาน (Username) | อย่างน้อย 4 ตัวอักษร, มีตัวพิมพ์ใหญ่อย่างน้อย 1 ตัว, ต้องมีทั้งตัวอักษรภาษาอังกฤษและตัวเลข และต้องไม่ซ้ำกับที่มีในระบบ (ระบบเตือนทันทีถ้าซ้ำ) |
| อีเมล | ต้องเป็น **Gmail (`@gmail.com`) เท่านั้น** ใช้รับรหัส OTP ตอนลืมรหัสผ่าน |
| รหัสผ่าน | อย่างน้อย 6 ตัวอักษร, มีตัวพิมพ์ใหญ่ 1 ตัว, ตัวพิมพ์เล็ก 1 ตัว และอักขระพิเศษ 1 ตัว (เช่น `!@#$%^&*`) |

**ขั้นตอนที่ 2/2 — ข้อมูลโปรไฟล์**

- ตำแหน่ง: QA Tester, Developer, Business Analyst, System Analyst หรือ Super Admin
- ชื่อ-นามสกุลจริง และแผนก/ทีม
- ติ๊กยินยอมให้เก็บข้อมูล (บังคับ)

**ผลการสมัคร**
- ตำแหน่งทั่วไป: เข้าสู่ระบบได้ทันที
- **Super Admin:** ต้องรอ Super Admin หลักอนุมัติก่อน ระบบจะส่งอีเมลแจ้งผลไปที่อีเมลที่สมัครไว้

### เข้าสู่ระบบ

- กรอกชื่อผู้ใช้และรหัสผ่าน แล้วกด **เข้าสู่ระบบ**
- พิมพ์รหัสผิด **3 ครั้ง** บัญชีจะถูกล็อก **60 วินาที** (ปุ่มจะนับถอยหลังให้เห็น) และระบบส่งอีเมลแจ้งเตือนเจ้าของบัญชี
- ระบบจำการเข้าสู่ระบบไว้ ถ้ารีเฟรชหน้าเว็บจะยังอยู่ในระบบ

### ออกจากระบบอัตโนมัติ

ถ้า **ไม่มีการใช้งานเลยนาน 10 นาที** (ไม่คลิก ไม่พิมพ์ ไม่เลื่อนหน้าจอ) ระบบจะออกจากระบบเองเพื่อความปลอดภัย แค่ขยับเมาส์หรือเลื่อนหน้าจอก็นับว่ายังใช้งานอยู่

### ลืมรหัสผ่าน

1. กด **ลืมรหัสผ่าน?** ที่หน้าเข้าสู่ระบบ แล้วกรอกชื่อผู้ใช้งาน
2. ระบบส่งรหัส OTP 6 หลักไปที่อีเมลที่ผูกกับบัญชี (หน้าจอจะแสดงอีเมลแบบปิดบางส่วน)
3. กรอก OTP ภายใน **5 นาที** แล้วตั้งรหัสผ่านใหม่

ข้อจำกัด: ขอ OTP ได้ไม่เกิน 3 ครั้งต่อ 10 นาที และกรอก OTP ผิดได้ไม่เกิน 5 ครั้ง ถ้าบัญชียังไม่มีอีเมล จะกู้รหัสผ่านเองไม่ได้ ให้ติดต่อ Super Admin เพื่อรีเซ็ตรหัสผ่านหรือตั้งอีเมลให้

## 5. สร้างข้อมูลทดสอบ

### ช่องที่ต้องกรอก

| ช่อง | บังคับ | คำอธิบาย |
| :--- | :--- | :--- |
| วาง Script โครงสร้างข้อมูล (CREATE TABLE...) | Rule-Based: บังคับ / Legacy: ไม่บังคับแต่แนะนำ | DDL ของตาราง ระบบใช้กำหนดชื่อคอลัมน์ ชนิดข้อมูล และข้อจำกัด เช่น `NOT NULL`, `PRIMARY KEY` |
| ข้อกำหนดเพิ่มเติม (Prompt Addition) | ไม่บังคับ | เงื่อนไขเป็นภาษาคน เช่น "amount อยู่ในช่วง 500–5000 บาท" ใช้ใน Legacy Mode |
| ประเภท Database (Dialect) | บังคับ | PostgreSQL, MySQL, MS SQL, Oracle หรือ MongoDB มีผลกับรูปแบบสคริปต์ที่ได้ |
| จำนวนแถวที่ต้องการ (Rows) | บังคับ | มากกว่า 0 สูงสุด **300 แถวต่อครั้ง** |
| ข้อมูลที่ต้องการสร้าง | บังคับ | คำอธิบายสั้น ๆ ว่าเป็นข้อมูลอะไร เช่น "รายได้จากค่าคอมมิชชัน" |
| ชื่อตาราง (Table Name) | บังคับ | ใช้ในสคริปต์ SQL และใช้ค้นหากฎเฉพาะตารางใน Rule-Based Mode |
| อนุญาตให้มีค่าว่าง (Allow Null) | ไม่บังคับ | **ปิด:** ทุกคอลัมน์ต้องมีค่า แม้ DDL หรือข้อกำหนดเพิ่มเติมจะบอกว่าเป็น NULL ได้ ระบบจะสร้างค่าที่สมเหตุสมผลใส่แทน / **เปิด:** ว่างได้ ยกเว้นคอลัมน์ที่ DDL กำหนด NOT NULL |
| Rule-Based Mode | ไม่บังคับ | เปิด = สร้างด้วยกฎในชีต / ปิด = สร้างด้วย AI |

### รูปแบบโครงสร้างตารางที่รองรับ

ช่อง "วาง Script โครงสร้างข้อมูล" รับได้ 2 รูปแบบ ระบบดูเองว่าเป็นแบบไหน

**แบบที่ 1 — SQL ปกติ**
```sql
CREATE TABLE users (id INT PRIMARY KEY, name VARCHAR(50) NOT NULL);
```

**แบบที่ 2 — คัดลอกจากผล Query ใน DBeaver**

บรรทัดแรกเป็น `CREATE TABLE ชื่อตาราง` บรรทัดต่อมาขึ้นต้นด้วย `(` แล้วตามด้วยบรรทัดละ 1 คอลัมน์ เรียงเป็น `column_name`, `data_type`, `character_maximum_length`, `is_nullable` (คั่นด้วย Tab ตามที่คัดลอกมาจาก DBeaver)

```
CREATE TABLE payment_ord_rider
(id	bigint		NO
period	character varying	10	YES
```

- ช่องความยาวที่เป็น Null (เช่นคอลัมน์ `id` ที่เป็น `bigint`) เว้นว่างได้
- `is_nullable` = `NO` คือห้ามว่าง, `YES` คือว่างได้
- ใส่วงเล็บปิด `)` ท้ายสุดหรือไม่ใส่ก็ได้ และถ้ามีแถวหัวตาราง (`column_name ...`) ติดมา ระบบจะข้ามให้
- ระบบแปลงเป็น SQL ปกติให้อัตโนมัติก่อนสร้างข้อมูล ตัวอย่างข้างบนจะกลายเป็น
  ```sql
  CREATE TABLE payment_ord_rider (
    id bigint NOT NULL,
    period character varying(10) NULL
  );
  ```

### Rule-Based Mode

1. เปิดสวิตช์ **Rule-Based Mode**
2. วาง DDL Script (บังคับ ระบบต้องรู้รายชื่อคอลัมน์ก่อนจึงจะหากฎได้)
3. กด **สร้างข้อมูลทดสอบ**

ระบบจะหากฎของทุกคอลัมน์ในชีต `RuleTemplates` โดยใช้กฎเฉพาะตาราง (มี `table_name` ตรงกับชื่อตาราง) ก่อน ถ้าไม่มีจึงใช้กฎกลางที่ใช้ได้ทุกตาราง

**ถ้าขึ้นข้อความ "ไม่พบข้อมูลของคอลัมน์ [...] ในฐานข้อมูล":** มีคอลัมน์ที่ยังไม่มีกฎ ระบบจะ**ไม่**สร้างข้อมูลให้เลย (ไม่เดาเอง) ทางแก้:
- ผู้ใช้ทั่วไป: ส่งคำขอถึงผู้ดูแลระบบผ่านเมนู **ติดต่อผู้ดูแลระบบ** (รูปแบบฟอร์ม ระบุชื่อตารางและคอลัมน์) หรือปิด Rule-Based Mode แล้วใช้ Legacy Mode แทน
- Super Admin: เพิ่มกฎตาม [หัวข้อ 14](#14-สำหรับ-super-admin-เพิ่มและแก้กฎของ-rule-based-mode)

### Legacy Mode (AI)

1. ปิดสวิตช์ Rule-Based Mode
2. วาง DDL (แนะนำ) และพิมพ์ข้อกำหนดเพิ่มเติม
3. กด **สร้างข้อมูลทดสอบ**

**ปุ่ม "ใส่แม่แบบ"** (มุมขวาของหัวข้อ "ข้อกำหนดเพิ่มเติม") เติมแม่แบบการเขียนเงื่อนไขให้ แล้วแก้เฉพาะส่วนที่อยู่ในวงเล็บ `[ ]` และลบบรรทัดที่ไม่ใช้ทิ้ง ตัวอย่างหลังแก้:

```
สร้างข้อมูลการชำระเงินตามรูปแบบต่อไปนี้
* id เป็นตัวเลขเรียงต่อกัน เริ่มที่ 1001
* period อยู่ในรูปแบบ "YYYYMM" เช่น 202609
* status มีค่าเป็น 'A' เสมอ
* amount อยู่ระหว่าง 500 ถึง 50,000 บาท ทศนิยม 2 ตำแหน่ง
```

จำนวนรายการไม่ต้องเขียนในข้อกำหนด ให้ใส่ที่ช่อง "จำนวนแถวที่ต้องการ (Rows)" แทน ข้อกำหนดเพิ่มเติมใช้สร้างข้อมูลใน Legacy Mode ส่วน Rule-Based Mode สร้างข้อมูลจากกฎในชีตเท่านั้น

เมื่อมี DDL ระบบจะใช้โค้ดตรวจและปรับผลลัพธ์จาก AI ให้ตรงกับ DDL อีกชั้น (คอลัมน์ ลำดับคอลัมน์ ชนิดข้อมูล `NOT NULL` และ `PRIMARY KEY`)

**แถบโควตา AI** (ใต้ปุ่มสร้างข้อมูล) แสดงจำนวนครั้งที่เรียก AI ใน 60 วินาทีล่าสุด เทียบกับเพดาน 20 ครั้งต่อนาที การกดสร้าง 1 ครั้งเรียก AI 2 ครั้ง (สร้างข้อมูล 1 ครั้ง + ตรวจคุณภาพ 1 ครั้ง) ถ้าใกล้เต็มหรือ Gemini แจ้งโควตาเต็ม ระบบจะบอกให้รอกี่วินาที

### Reference Column Lock (อ้างอิงข้อมูลจากชุดที่เคย Commit)

ใช้เมื่อต้องการให้ตารางใหม่มีค่าตรงกับข้อมูลที่ Commit ไว้แล้ว เช่น ให้ `customer_id` ในตาราง `orders` เป็นรหัสที่มีจริงในตาราง `customers` (ใช้ทดสอบ Foreign Key)

1. เปิด **Reference Lock**
2. เลือกวันที่ แล้วเลือกรอบข้อมูลที่เคย Commit ไว้ของวันนั้น
3. ติ๊กคอลัมน์ที่ต้องการให้ค่าตรงกับข้อมูลเดิม
4. กดสร้างข้อมูลตามปกติ

ค่าของคอลัมน์ที่ติ๊กจะสุ่มหยิบจากแถวเดิมตรง ๆ ไม่ผ่าน AI ถ้าติ๊กหลายคอลัมน์ แต่ละแถวใหม่จะได้ค่าจากแถวต้นฉบับเดียวกันเสมอ (คู่ข้อมูลไม่หลุด) ส่วนคอลัมน์อื่นสร้างใหม่ตามปกติ

ปุ่มข้างช่องเลือกรอบ: 🔄 รีเฟรชรายการ และ 🗑 ลบรอบข้อมูลที่เลือก (ลบออกจาก Google Sheet ถาวร)

### แนบภาพ Schema / ER Diagram (ไม่บังคับ)

แนบรูปโครงสร้างตารางหรือ ER Diagram ให้ AI อ่านประกอบ (ใช้กับ Legacy Mode) รูปจะถูกเก็บใน Google Drive ของระบบ กดที่รูปย่อเพื่อดูขนาดใหญ่

### Prompt ที่บันทึกไว้ (ใช้ซ้ำได้)

- **บันทึก:** ตั้งชื่อในช่อง "ตั้งชื่อ Prompt ปัจจุบัน" แล้วกด **บันทึก** จะเก็บทุกช่องในฟอร์ม รวมรูปที่แนบและการตั้งค่า Reference Lock
- **โหลดมาใช้:** เลือกจากรายการ แล้วกด **โหลดมาใช้** ทุกช่องจะถูกเติมให้
- **ลบ:** เลือกแล้วกดไอคอนถังขยะ

### ยกเลิกระหว่างสร้าง

กด **ยกเลิกการสร้างข้อมูล** ได้ระหว่างที่ระบบกำลังประมวลผล

## 6. จุดพัก: ตรวจสอบข้อมูลก่อนนำเข้า Dashboard

หลังสร้างข้อมูลเสร็จ ระบบจะหยุดที่หน้าต่างนี้ก่อนเสมอ และตรวจ 4 ข้อ:

1. จำนวนแถวที่ได้ตรงกับที่ขอหรือไม่
2. คอลัมน์บังคับครบหรือไม่ (ถ้าผู้ดูแลระบบตั้งค่าไว้ในชีต `ColumnSchemaConfig`)
3. โครงสร้างข้อมูล (ค่าว่าง รูปแบบฟิลด์)
4. เนื้อหาตรงกับเงื่อนไขที่กรอกไว้หรือไม่ (AI ตรวจซ้ำ)

**ผลที่แสดง**

| รายการ | ความหมาย |
| :--- | :--- |
| ตรงตามเงื่อนไข | เปอร์เซ็นต์ที่ข้อมูลตรงกับเงื่อนไข ต้อง ≥ **70%** |
| ความน่าเชื่อถือของข้อมูล | ต้อง ≥ **90%** |
| ระดับข้อมูล | ขั้นสูง / ปานกลาง / พื้นฐาน หรือ "ไม่ผ่านเกณฑ์ขั้นต่ำ" |
| ข้อสังเกต | คอลัมน์ที่ถูกตัดทิ้ง คอลัมน์บังคับที่ขาด ปัญหาโครงสร้าง และข้อสังเกตจาก AI |

**ตัดสินใจ**
- **ยืนยันนำเข้าสู่ Dashboard:** นำข้อมูลไปที่หน้าตรวจสอบข้อมูล (ยังไม่บันทึกลงฐานข้อมูล)
- **ยกเลิก / ไม่นำเข้าข้อมูลนี้:** ทิ้งชุดนี้ แล้วปรับเงื่อนไขสร้างใหม่

ถ้าคะแนนต่ำกว่าเกณฑ์ ระบบจะไม่ให้นำเข้า

## 7. ตรวจสอบข้อมูลและบันทึกลงฐานข้อมูล (Commit)

### ตารางข้อมูล

- **คลิกที่ช่องเพื่อแก้ไข** ได้ทุกช่อง แถวที่ถูกแก้จะถูกทำเครื่องหมายว่า "มีการแก้ไขโดยมนุษย์"
- **ค้นหา:** พิมพ์ในช่องค้นหา กรองแบบทันที
- **กรองตามชื่อหัวข้อ / กรองค่าที่ซ้ำ:** เลือกคอลัมน์ แล้วเลือกค่าที่ต้องการดู
- **แก้ไขทั้งหมด (Batch Update):** หลังกรองแล้ว เลือกฟิลด์และใส่ค่าใหม่ ระบบจะแทนค่าในทุกแถวที่ผ่านการกรองพร้อมกัน
- **ล้างตัวกรอง:** กลับไปแสดงข้อมูลทั้งหมด
- **คัดลอกตาราง / ส่งออกไฟล์ .csv**
- ใต้ตารางแสดงคะแนนตรงตามเงื่อนไข ความน่าเชื่อถือ และระดับข้อมูล ถ้ามีจุดที่ไม่ตรงเงื่อนไข จะมีข้อความสีแดงแจ้งไว้ ควรแก้ก่อน Commit

### บันทึกลงฐานข้อมูล (Commit)

1. **ล้างตัวกรองก่อน** (ระหว่างกรองอยู่จะ Commit ไม่ได้ เพื่อไม่ให้บันทึกข้อมูลไม่ครบ)
2. พิมพ์**รหัสผ่านของคุณ**ในช่อง "รหัสผ่านเพื่อยืนยัน Commit" ปุ่มจะปลดล็อกเมื่อรหัสถูกต้อง
3. กด **บันทึกลงฐานข้อมูล** → ยืนยัน

ข้อมูลจะถูกบันทึกลงแท็บ `GeneratedDatasets` ใน Google Sheet และไปปรากฏในเมนูประวัติ Commit

## 10. ติดต่อผู้ดูแลระบบ

### สำหรับผู้ใช้ทั่วไป

กด **+ สร้างคำขอใหม่** เลือกรูปแบบได้ 2 แบบ:

| รูปแบบ | ใช้เมื่อ | ช่องที่กรอก |
| :--- | :--- | :--- |
| ฟอร์ม | ขอให้เพิ่มกฎ/ข้อมูลของคอลัมน์ที่ยังไม่มี | ชื่อตาราง, คอลัมน์ที่ต้องการ, เหตุผลการใช้งาน |
| แชท | สอบถามเรื่องอื่น | ข้อความ |

- เปิดคำขอเพื่อคุยตอบโต้กับผู้ดูแลระบบได้ (Enter = ส่ง, Shift+Enter = ขึ้นบรรทัดใหม่)
- สถานะ: **เปิดอยู่** / **รอตอบกลับ** / **ปิดแล้ว** และมีสถานะ "อ่านแล้ว"

### สำหรับ Super Admin

- เห็นคำขอของผู้ใช้ทุกคนในระบบ (ไม่มีปุ่มสร้างคำขอ)
- ตอบกลับ **ปิดเรื่อง** หรือ **เปิดเรื่องอีกครั้ง**
- ลบคำขอทีละรายการ หรือเลือกหลายรายการแล้ว **ลบที่เลือก** (ลบได้เฉพาะเรื่องที่ปิดแล้ว)
- **ล้างคำขอเก่าที่ปิดแล้ว:** ลบเรื่องที่ปิดเกินจำนวนวันที่กำหนดทั้งหมดในครั้งเดียว

การลบคำขอเป็นการลบถาวร รวมข้อความสนทนาทั้งหมด

## 14. สำหรับ Super Admin: เพิ่มและแก้กฎของ Rule-Based Mode

กฎทั้งหมดอยู่ในแท็บ **`RuleTemplates`** ของ Google Sheet (เปิดได้จากปุ่มเปิดชีตกฎที่หัว Dashboard) **1 แถว = กฎของ 1 คอลัมน์**

### โครงสร้างแถว

| คอลัมน์ | ความหมาย |
| :--- | :--- |
| `table_name` | **เว้นว่าง** = กฎกลาง ใช้ได้กับทุกตารางที่มีคอลัมน์ชื่อนี้ / **ใส่ชื่อตาราง** = กฎเฉพาะตารางนั้น (ใช้ก่อนกฎกลาง) |
| `column_name` | ชื่อคอลัมน์ ต้องตรงกับชื่อใน DDL (ไม่สนตัวพิมพ์เล็ก-ใหญ่) |
| `generator` | ชนิดตัวสร้างค่า (ดูตารางด้านล่าง) |
| `param_json` | ค่าตั้งของตัวสร้าง เขียนเป็น JSON |
| `notes` | หมายเหตุ ไม่มีผลกับการทำงาน |

### ชนิดตัวสร้างค่า (generator)

| generator | สร้างอะไร | param_json ตัวอย่าง |
| :--- | :--- | :--- |
| `sequential` | เลขเรียงต่อกัน มีคำนำหน้าได้ | `{"prefix": "CUST-", "digits": 6, "start": 1}` → CUST-000001, CUST-000002 |
| `enum` | สุ่มจากรายการที่กำหนด | `{"values": ["Pending", "Shipped", "Completed"]}` |
| `number_range` | ตัวเลขสุ่มในช่วง | `{"min": 1000, "max": 50000, "decimals": 2}` |
| `date_range` | วันที่สุ่มในช่วง | `{"start": "2026-01-01", "end": "2026-12-31"}` |
| `pattern` | ข้อความตามรูปแบบ (`#` = ตัวเลข 0–9, `@` = ตัวอักษร A–Z, อื่น ๆ ใช้ตามตัว) | `{"pattern": "POL-####-@@"}` → POL-4821-KQ |
| `thai_citizen_id` | เลขบัตรประชาชน 13 หลัก checksum ถูกต้อง | เว้นว่าง |
| `phone_th` | เบอร์มือถือไทย | เว้นว่าง |
| `email_from_name` | อีเมลสร้างจากคอลัมน์ชื่อในแถวเดียวกัน | `{"nameColumn": "full_name"}` (ตารางต้องมีคอลัมน์ `full_name` ด้วย) |
| `percent_of` | ค่าเป็นเปอร์เซ็นต์ของอีกคอลัมน์ในแถวเดียวกัน | `{"baseColumn": "sum_assured", "percentMin": 1, "percentMax": 8}` |

ดูตัวอย่างกฎจริงได้ในไฟล์ `templates/RuleTemplates_Insurance.xlsx` ของ repo (ราว 96 กฎด้านประกัน)

### ตัวอย่าง: เพิ่มกฎเมื่อผู้ใช้แจ้งว่าขาดคอลัมน์

ผู้ใช้แจ้งว่าตาราง `orders` ขาดกฎของ `order_status` และ `order_date`

| table_name | column_name | generator | param_json | notes |
| :--- | :--- | :--- | :--- | :--- |
| | `order_status` | `enum` | `{"values": ["Pending", "Shipped", "Completed", "Cancelled"]}` | สถานะคำสั่งซื้อ |
| `orders` | `order_date` | `date_range` | `{"start": "2026-09-01", "end": "2026-09-30"}` | เฉพาะตาราง orders |

- แถวแรกเว้น `table_name` จึงใช้ได้กับทุกตารางที่มีคอลัมน์ `order_status`
- แถวที่สองใช้เฉพาะตาราง `orders` ตารางอื่นที่มี `order_date` จะใช้กฎกลาง (ถ้ามี)
- เพิ่มเสร็จแล้วให้ผู้ใช้กดสร้างข้อมูลใหม่ได้ทันที ไม่ต้อง Deploy ใหม่ จากนั้นปิดเรื่องในเมนูติดต่อผู้ดูแลระบบ

### ข้อควรระวัง

- `param_json` ต้องเป็น JSON ถูกต้อง: ใช้เครื่องหมายคำพูดคู่ `"` เท่านั้น และระวัง Google Sheets แปลงเป็นตัวเลขหรือวันที่เอง
- ถ้ามีกฎซ้ำ (`table_name` + `column_name` เดียวกัน) ระบบใช้แถวที่อยู่ล่างสุด
- กฎแบบ `email_from_name` และ `percent_of` ต้องมีคอลัมน์อ้างอิงอยู่ในตารางเดียวกัน

## 15. สำหรับ Super Admin: เมนูเครื่องมือแอดมินใน Google Sheet

เปิด Google Sheet แล้วใช้เมนู **เครื่องมือแอดมิน** ด้านบน

| เมนู | ใช้ทำอะไร |
| :--- | :--- |
| ล้างข้อมูลทดสอบเก่าใน ActivityLogs / GeneratedDatasets | ลบข้อมูลทั้งหมดในแท็บนั้น (เหลือแค่หัวตาราง) |
| ย้ายข้อมูลเก่าใน ActivityLogs / QualityScores / GeneratedPromptLogs ไปแท็บสำรอง | ย้ายข้อมูลที่เก่ากว่า 6 เดือนออกจากแท็บหลัก ช่วยให้ระบบไม่ช้า |
| เปิด/ปิดระบบย้ายข้อมูลเก่าไปแท็บสำรองอัตโนมัติ | ทำงานเองทุกวันที่ 1 ของเดือน |
| ล้างไฟล์รูปที่ไม่มีการอ้างอิงแล้วใน Drive | ลบรูป Schema ที่ไม่มี Prompt หรือประวัติใดอ้างถึงแล้ว |
| ดูสรุปขนาดข้อมูลปัจจุบันของแต่ละชีต | ดูจำนวนแถว (เกิน 3,000 แถวควรเริ่มย้ายข้อมูลเก่า) |
| ตรวจสอบข้อมูลผิดปกติในชีต Users | หาแถวที่ข้อมูลผู้ใช้ผิดรูปแบบ |
| สำรองข้อมูลทั้งไฟล์เดี๋ยวนี้ | คัดลอกทั้งสเปรดชีตไปเก็บในโฟลเดอร์สำรองใน Drive (เก็บล่าสุด 8 ชุด) |
| เปิด/ปิดระบบสำรองข้อมูลอัตโนมัติ | สำรองเองทุกวันจันทร์ |
| ตรวจสอบความพร้อมก่อน Deploy | เช็ก API Key, แท็บครบ, มี Super Admin และสิทธิ์แชร์ชีต |
| สร้างรายงานสรุประบบเป็น PDF | สรุปการใช้งานและความปลอดภัยของระบบ |

**แนะนำ:** เปิดระบบสำรองข้อมูลอัตโนมัติและระบบย้ายข้อมูลเก่าอัตโนมัติไว้ตั้งแต่แรก
